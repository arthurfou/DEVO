🔭 Présentation du projet

DEVO est un système d'odométrie visuelle basé sur les événements (event camera). Contrairement aux caméras classiques qui capturent des frames à intervalle régulier, une caméra événementielle (type DAVIS, DVS) produit un flux asynchrone d'événements — chaque pixel émet un signal dès que sa luminosité change. DEVO estime la trajectoire 6-DoF de la caméra uniquement depuis ces événements, sans frame RGB.

ℹ️
DEVO est le premier système monoculaire event-only à atteindre des performances compétitives sur des benchmarks réels. Il s'appuie sur un suivi de patches parses différentiable couplé à un bundle adjustment différentiable, le tout end-to-end.

Principe général

Les événements bruts sont d'abord convertis en grilles de voxels à 5 bins temporels (format (B, N, 5, H, W)). Ces voxels sont traités par un réseau convolutif pour extraire des features, puis un petit nombre de patches (zones d'intérêt) sont sélectionnés et suivis d'une frame à l'autre. L'optimisation conjointe des poses et profondeurs se fait par bundle adjustment différentiable.

Pipeline simplifié
1
Événements bruts → Voxel grid 5 bins (5 canaux temporels, normalisation std/rescale)
↓
2
Encodeur convolutif (BasicEncoder4Evs) → Feature map stride-4
↓
3
Sélection de patches (Scorer / Gradient / Random) → 80 points d'intérêt par frame
↓
4
Reprojection des patches (poses courantes) → Volumes de corrélation (altcorr CUDA)
↓
5
Opérateur de mise à jour (Update / GRU) → delta de flot optique + poids d'incertitude
↓
6
Bundle Adjustment différentiable → raffinement poses + profondeurs
↓
7
Gestion des keyframes (suppression des frames à faible mouvement)
↓
8
Interpolation des poses manquantes → Trajectoire 6-DoF finale

Entraînement

Séquence images (B, N, C, H, W)
        │
        ▼
eVONet.forward(images, poses_gt, disps_gt, intrinsics)
  ├─ Normalisation
  ├─ Patchifier → patches, fmap, gmap, imap
  ├─ Init poses (damped linear)
  └─ Boucle STEPS fois :
       ├─ reproject + corr
       ├─ Update GRU → delta, weights

        │
        ▼

  ├─ Flow loss : ||proj_estimated - proj_gt||  (min sur pixels du patch)

Ce fichier contient la classe DEVO, le cœur du système. Elle gère l'état complet du tracker : poses, patches, features, correspondances entre frames. C'est le point d'entrée unique lors de l'inférence.

__call__ — Point d'entrée principal

DEVO.__call__(tstamp, image, intrinsics, scale=1.0)
Traite une nouvelle frame et met à jour les poses. Appelé une fois par frame lors de l'inférence.
tstamp: float image: Tensor (1, 1, 5, H, W) intrinsics: Tensor (4,) scale: float = 1.0
Étapes internes
1
Normalisation : applique la méthode de normalisation choisie (none/rescale/std/std2) sur le voxel grid d'événements
2
Patchification : network.patchify(image) → extrait fmap, gmap, imap, patches, index. Stockage dans les buffers circulaires.
3
Initialisation profondeur : profondeur inverse initialisée aléatoirement (distribution uniforme, valeur typique ~ 0.5 inverse)
4
Modèle de mouvement : prédit la pose de la nouvelle frame via DAMPED_LINEAR (extrapolation amortie depuis les 2 dernières poses)
5
Ajout des arêtes : crée des correspondances patch→frame pour la fenêtre courante (OPTIMIZATION_WINDOW frames)
6
motion_probe() : mesure le mouvement médian des patches. Si insuffisant (< seuil), la frame n'est pas marquée comme keyframe
7
update() : reprojection + corrélation + update + BA
8
keyframe() : supprime les frames à faible mouvement du buffer
💡
Normalisation std2 (par défaut dans eVONet) : standardise sur l'ensemble de la séquence. std : zero-mean, unit variance par frame. rescale : normalise positif/négatif séparément dans [-1,0) et (0,1].

update() — Boucle d'optimisation

DEVO.update()
Exécute un cycle complet reprojection → corrélation → update GRU → bundle adjustment.
# Simplifié :
def update(self):
    coords = self.reproject()             # (E, P, P, 2)
    corr = self.corr(coords)               # volume de corrélation
    net, (delta, weight, _) = self.network.update(
        self.net, self.inp, corr, coords, self.ii, self.jj, self.kk
    )
    self.poses, self.patches = BA(
        self.poses, self.patches, self.intrinsics,
        coords + delta, weight,
        self.ii, self.jj, self.kk, ...
    )

keyframe() — Gestion des keyframes

DEVO.keyframe()
Supprime les frames à faible mouvement du buffer glissant. Implémentation style DPVO.

Logique de suppression :

  1. Calcule le flot optique entre chaque frame et la frame courante (flow_mag)
  2. Si le flot médian est inférieur à KEYFRAME_THRESH (12.5 pixels), la frame est supprimée
  3. Sa pose relative est stockée dans self.delta[t] pour l'interpolation finale
  4. Les patches plus anciens que PATCH_LIFETIME frames sont supprimés des arêtes
ℹ️
Le dictionnaire self.delta mappe timestamp → (pose_relative, timestamp_parent). Cela permet à terminate() de reconstruire toutes les poses, même celles des frames non-keyframe.

terminate() — Finalisation

DEVO.terminate() → (poses_np, tstamps_np)
Interpolation des poses manquantes et retour de la trajectoire complète. Optionnellement, exporte un nuage de points 3D en PLY.
# Interpolation des poses manquantes
for t in sorted(self.delta.keys()):
    pose_rel, t_parent = self.delta[t]
    poses[t] = pose_rel * poses[t_parent]  # composition SE3

# Export PLY si map_path défini
if self.map_path:
    self._export_map()

_export_map() et _write_ply()

Export du nuage de points 3D : les patches sont reprojetés dans le repère monde, les points invalides (derrière la caméra, NaN) sont filtrés, et le résultat est écrit en format PLY binaire.

Autres méthodes

motion_probe() → float
Mesure le mouvement médian entre les patches de la frame précédente et la frame courante. Sert à vérifier si la caméra bouge assez pour créer un nouveau keyframe.
reproject(indicies=None) → Tensor
Reprojette les patches depuis la frame i vers la frame j en utilisant les poses courantes. Retourne les coordonnées 2D dans la frame j.
corr(coords, indicies=None) → Tensor
Calcule les volumes de corrélation locale à plusieurs échelles en utilisant altcorr (CUDA). Utilisé pour comparer les features entre frames.
load_weights(network) → None
Charge les poids pré-entraînés depuis un fichier .pth. Extrait aussi les attributs du réseau (dim_inet, dim_fnet, RES, P).

📐 devo/ba.py — Bundle Adjustment différentiable

Implémente un Bundle Adjustment (BA) différentiable permettant d'optimiser conjointement les poses caméra et les profondeurs des patches. Différentiable signifie que les gradients peuvent traverser l'optimisation pour entraîner le réseau.

ℹ️
Le BA utilise la réduction de Schur pour éliminer les variables de profondeur et ne résoudre que les poses, réduisant drastiquement la taille du système linéaire. Les profondeurs sont ensuite recalculées par substitution arrière.

Fonction principale BA

BA(poses, patches, intrinsics, targets, weights, lmbda, ii, jj, kk, bounds, ep=100.0, fixedp=1, structure_only=False) → (poses, patches)
Paramètres clés
ParamètreRôle
posesPoses SE3 courantes — optimisées en sortie
patchesPatches 3D (x,y,depth) — profondeurs optimisées en sortie
targetsCoordonnées 2D cibles = coords reprojection + delta prédit par le GRU
weightsPoids d'observation par arête (sortie du GRU)
lmbdaTerme de régularisation (damping Levenberg-Marquardt)
ii, jj, kkArêtes du graphe : patch kk observé de frame ii vers frame jj
epDamping additionnel sur la diagonale du Hessien (100.0)
fixedpNombre de poses fixées (première pose fixée, = 1)
structure_onlySi True : optimise seulement les profondeurs, poses figées
Étapes du BA
1
Reprojection : transforme les patches 3D selon les poses courantes → résidus r = targets − projected
2
Jacobiens : Ji (∂proj/∂pose_i), Jj (∂proj/∂pose_j), Jz (∂proj/∂depth)
3
Hessien : Bii, Bij, Bjj (blocs pose-pose), Eik, Ejk (pose-depth), C (depth-depth)
4
Schur complement : S = B − E C⁻¹ Eᵀ → résout S·Δpose = b
5
Substitution arrière : Δdepth = C⁻¹(g − Eᵀ Δpose)
6
Rétraction : applique Δpose via l'exponentielle de Lie (lietorch), Δdepth additivement

CholeskySolver

CholeskySolver(torch.autograd.Function)
Résout Ax=b via factorisation de Cholesky. Différentiable : le backward calcule les gradients par rapport à A et b.
📡 devo/projective_ops.py — Géométrie projective

Fonctions de géométrie projective utilisées par ba.py et devo.py pour transformer les patches entre frames.

iproj(patches, intrinsics) → Tensor (B, N, P, P, 4)
Projection inverse : convertit les patches 2D avec profondeur en coordonnées 3D homogènes [X, Y, 1, 1/Z]. Utilise les intrinsèques [fx, fy, cx, cy].
proj(X, intrinsics, depth=False) → Tensor (B, N, P, P, 2)
Projection : projette des points 3D en coordonnées image 2D [x, y]. Optionnellement retourne aussi la profondeur Z.
transform(poses, patches, intrinsics, ii, jj, kk, depth=False, valid=False, jacobian=False, tonly=False)
Reprojection complète : reprojette le patch kk de la frame ii vers la frame jj. Calcule Gij = Tj × Ti⁻¹ pour la transformation relative. Options : masque de validité (Z > 0.2), jacobiens pour BA, mode translation-only.
point_cloud(poses, patches, intrinsics, ix) → Tensor
Génère le nuage de points 3D dans le repère monde depuis les patches et les poses. Utilisé pour la visualisation et l'export PLY.
flow_mag(poses, patches, intrinsics, ii, jj, kk, beta=0.3) → Tensor
Calcule la magnitude du flot optique entre paires de frames. Combine deux composantes : flot de rotation (pondéré par beta=0.3) et flot de translation (pondéré par 1−beta=0.7). Utilisé dans keyframe() pour décider de supprimer une frame.
🧱 devo/blocks.py — Briques neuronales
GatedResidual

Connexion résiduelle avec gate. Formule : x + gate(x) × residual(x) où gate = Linear→Sigmoid et residual = Linear→ReLU→Linear. Utilisé dans le GRU de l'Update.

SoftAgg

Agrégation douce par index avec attention. Agrège les features de plusieurs éléments partageant le même index via scatter_softmax. Utilisé pour agréger sur les patches (kk) et sur les paires de frames (ii, jj).

LayerNorm1D

LayerNorm pour tenseurs 1D avec ajustement de la dimension canal.

GradientClip / GradientZero

GradientClip : clamp les gradients dans [−0.01, 0.01], remplace NaN par 0. GradientZero : annule les gradients dépassant un seuil GRAD_CLIP. Protègent l'entraînement des explosions de gradient.

🏋️ train.py — Entraînement

Script d'entraînement distribué (PyTorch DDP — DistributedDataParallel) sur plusieurs GPU.

Organisation de l'entraînement

1
Setup DDP : initialisation du groupe de processus distribués, allocation des GPU
2
Dataset Factory : crée des datasets TartanAir (RGB, EVS, E2VID) avec les splits définis dans splits/
3
Modèle : instancie eVONet (events) ou VONet (RGB) selon la config
4
Boucle d'entraînement : forward → loss → backward → gradient clipping → optimizer step
5
Scheduler : OneCycleLR — learning rate augmente puis diminue sur la durée totale
6
Checkpointing : sauvegarde modèle + optimizer + scheduler tous les N steps

Composantes de la loss

ComposanteFormuleRôle
Flow lossminp∈patch ||proj_est(p) − proj_gt(p)||²Supervise le flot optique prédit contre la vérité terrain
Scorer lossPondérée par scores × poids BAEntraîne le Scorer à sélectionner les bons patches (optionnel)
Structure-onlyFlow loss, poses figéesPremiers 1000 steps : optimise seulement les profondeurs pour l'initialisation
💡
Le mode structure_only=True lors des 1000 premiers steps permet d'initialiser correctement les profondeurs avant de commencer à optimiser les poses. Cela évite de partir d'un mauvais état initial.
🏗️ Architecture du réseau de neurones
Input : Voxel grid (B, N, 5, H, W)  # 5 bins temporels
          │
          ├──── BasicEncoder4Evs (fnet, output_dim=128)
          │          Conv7x7(5→32,s2) → ResBlock(32→64,s1) → ResBlock(64→128,s2) → Conv1x1
          │          Output : (B, N, 128, H/4, W/4)
          │
          ├──── BasicEncoder4Evs (inet, output_dim=384)
          │          Conv7x7(5→32,s2) → ResBlock(32→64,s1) → ResBlock(64→128,s2) → Conv1x1(→384)
          │          Output : (B, N, 384, H/4, W/4)
          │
          └──── Scorer
                     Conv2d(5→8→16→32→1) → MaxPool(4)
                     Output : (B, N, H/4, W/4)  # scoring map

            ↓ PatchSelector._multi()
Patches sélectionnés : (B, N×M, 2)   # M=80 par frame

            ↓ Extraction features locales
gmap : (B, N×M, 128, P, P)           # features matching autour du patch
imap : (B, N×M, 384)                 # features contexte au centre

════════════════ Boucle itérative (STEPS=12) ════════════════

  ┌─ poses courantes + depths
  │
  ├─ transform()  →  coords (E, P, P, 2)
  │
  ├─ altcorr.corr()  →  corr_volume (E, lvls, 2r+1, 2r+1)
  │
  └─ Update.forward(net, imap, corr, coords, ii, jj, kk)
        c1,c2 : imap → inp_feat (dim)
        agg_kk : agrégation par patch kk
        agg_ij : agrégation par paire (ii,jj)
        GRU    : 2× GatedResidual + LayerNorm
        d      : → delta_flow (E, P, P, 2)
        w      : → weights (E, P, P, 2)  [0,1]

            ↓
        BA()
          Jacobiens : Ji(6D), Jj(6D), Jz(1D)
          Hessien + Schur complement
          CholeskySolver → Δposes
          Back-substitution → Δdepths
          Rétraction lietorch → poses, depths mis à jour

════════════════════════════════════════════════════════════
Output : poses (N, 7), timestamps (N,)
