DEVO — Les Events Camera en Python

Guide complet du pipeline : de evs.npy brut jusqu'à la trajectoire estimée.
Tous les extraits de code sont tirés directement du repo.

C'est quoi un event ?

Une caméra classique prend des photos à intervalle fixe (30 Hz, 60 Hz…). Une caméra événementielle (DVS — Dynamic Vision Sensor) fonctionne différemment : chaque pixel surveille indépendamment la luminosité et génère un event dès qu'il détecte un changement de log-luminosité au-dessus d'un seuil.

Définition d'un event Un event = un tuple (t, x, y, p) où :
• t = timestamp en microsecondes
• x, y = coordonnées du pixel qui a changé
• p = polarité : +1 si la luminosité a augmenté, 0 si elle a diminué

Dans DEVO, on utilise la caméra DVS346 (utilisée dans le dataset EVIMO) : résolution 260 × 346 pixels, générant jusqu'à ~570 millions d'events par séquence.

Comparaison frames vs events

Caméra classique (frame)Caméra événementielle (DVS)
Photo entière toutes les ~33 msChaque pixel indépendamment, ~µs de résolution
Motion blur à vitesse élevéePas de motion blur
Redondance (pixels statiques)Seulement ce qui bouge → très sparse
Output : tensor (H, W, 3) RGBOutput : liste d'events (N, 4)
Facile à utiliser avec les CNN classiquesBesoin d'une représentation intermédiaire
Idée clé de DEVO Pour utiliser un CNN sur les events, DEVO les convertit en une Voxel Grid : un tensor (5, H, W) où la dimension temporelle est discrétisée en 5 bins. C'est la représentation centrale de tout le pipeline.

① Chargement des données

Tout part de la fonction evimo_evs_iterator() dans utils/load_utils.py ligne 1305. C'est un générateur Python qui charge toutes les données et yield un voxel par frame. 

# utils/load_utils.py — ligne 1305
def evimo_evs_iterator(scenedir, stride=1, dT_ms=None, H=260, W=346, timing=False):

    # ── 1. Charger les intrinsèques depuis calib.txt
    calib_path = osp.join(scenedir, "calib.txt")
    fx, fy, cx, cy = load_intrinsics_evimo(calib_path)
    intrinsics = torch.from_numpy(np.array([fx, fy, cx, cy]))

    # ── 2. Charger les events
    evs = np.load(osp.join(scenedir, "evs.npy"))  # (N, 4) : [ts_µs, x, y, p]

    # ── 3. Charger la carte de rectification
    rectify_map = read_rmap(osp.join(scenedir, "rectify_map.h5"), H=H, W=W)

    # ── 4. Charger les timestamps de frames (délimitent les fenêtres temporelles)
    tss_imgs_us = sorted(np.loadtxt(osp.join(scenedir, "tss_imgs_us.txt")))
    if dT_ms is None:
        dT_ms = np.diff(tss_imgs_us).mean() / 1e3  # ≈ 25 ms pour EVIMO
    tss_imgs_us = tss_imgs_us[::stride]

    # ── 5. Convertir tous les events en voxels (pré-calcul)
    data_list = get_ecd_data(tss_imgs_us, evs, intrinsics, rectify_map, dT_ms, H, W)

    # ── 6. Yield un voxel à la fois vers le réseau
    for (voxel, intrinsics, ts_us) in data_list:
        yield voxel.cuda(), intrinsics.cuda(), ts_us

Calibration intrinsèque — load_intrinsics_evimo()

Les paramètres de la caméra sont stockés dans calib.txt sous la forme :
fx fy cx cy k1 k2 p1 p2
La fonction recalcule la matrice optimale après undistorsion : 

# utils/load_utils.py — ligne 1294
def load_intrinsics_evimo(calib_path):
    vals = np.loadtxt(calib_path)
    fx, fy, cx, cy = vals[:4]
    dist = vals[4:]                     # coefficients de distorsion [k1,k2,p1,p2]
    if len(dist) == 4:
        dist = np.append(dist, 0.0)   # ajoute k3=0 si manquant

    K = np.array([[fx, 0, cx], [0, fy, cy], [0, 0, 1]], dtype=np.float64)
    # getOptimalNewCameraMatrix recalcule K pour une image sans distorsion
    K_new, _ = cv2.getOptimalNewCameraMatrix(K, dist, (346, 260), alpha=0)
    return K_new[0,0], K_new[1,1], K_new[0,2], K_new[1,2]
Pourquoi recalculer K ? La matrice K de calib.txt correspond à l'image distordue. Après undistorsion, le centre optique et les focales changent légèrement. getOptimalNewCameraMatrix avec alpha=0 garantit que l'image rectifiée ne contient aucun pixel noir (pas de bords coupés).

② Slicing temporel — get_ecd_data()

C'est ici qu'on découpe le flux d'events en tranches temporelles, une par voxel. Chaque tranche correspond à environ 25 ms d'events. 

# utils/load_utils.py — ligne 635
def get_ecd_data(tss_imgs_us, evs, intrinsics, rectify_map,
                  DELTA_MS=None, H=180, W=240):
    data_list = []
    for (ts_idx, ts_us) in enumerate(tss_imgs_us):
        if ts_idx == len(tss_imgs_us) - 1:
            break

        # ── Définir la fenêtre temporelle ──
        if DELTA_MS is None:
            t0_us, t1_us = ts_us, tss_imgs_us[ts_idx + 1]   # fenêtre variable
        else:
            t0_us, t1_us = ts_us, ts_us + DELTA_MS * 1e3       # fenêtre fixe

        # ── Sélectionner les events dans [t0, t1[ ──
        evs_idx = np.where((evs[:, 0] >= t0_us) & (evs[:, 0] < t1_us))[0]

        if len(evs_idx) == 0:
            print(f"no events in range {ts_us*1e-3:.1f} - {t1_us*1e-3:.1f} ms")
            continue

        evs_batch = np.array(evs[evs_idx, :]).copy()
        # evs_batch.shape = (K, 4) avec K = nb d'events dans la fenêtre

        # ── Appliquer la rectification + créer le voxel ──
        if rectify_map is not None:
            rect = rectify_map[evs_batch[:, 2].astype(np.int32),   # y
                                evs_batch[:, 1].astype(np.int32)]    # x
            # rect.shape = (K, 2) → nouvelles coordonnées undistorted
            voxel = to_voxel_grid(rect[..., 0],    # x undistorted
                                    rect[..., 1],    # y undistorted
                                    evs_batch[:, 0],  # timestamps
                                    evs_batch[:, 3],  # polarités
                                    H=H, W=W, nb_of_time_bins=5)
        # voxel.shape = (5, 260, 346)
        data_list.append((voxel, intrinsics,
                           min((t0_us + t1_us) / 2, tss_imgs_us[ts_idx + 1])))

    return data_list  # liste de (voxel, intrinsics, timestamp_central)
Attention — le timestamp de sortie Le timestamp stocké est le milieu de la fenêtre (t0+t1)/2, pas t0. C'est ce timestamp qui sera associé à chaque pose dans la trajectoire de sortie.

③ Rectification (Undistortion)

Les lentilles des caméras introduisent une distorsion radiale (les droites semblent courbes aux bords). La rectify_map corrige ça : pour chaque event (x,y), on lit la position rectifiée dans la map. 

# Extrait de get_ecd_data() :
# evs_batch[:, 2] = colonne y des events
# evs_batch[:, 1] = colonne x des events

rect = rectify_map[evs_batch[:, 2].astype(np.int32),   # indexé par y
                    evs_batch[:, 1].astype(np.int32)]    # puis par x

# rect.shape = (K, 2)
# rect[:, 0] = nouvelles coordonnées x (float, peut être non-entier)
# rect[:, 1] = nouvelles coordonnées y (float, peut être non-entier)
Pourquoi les coordonnées rectifiées sont-elles flottantes ? L'undistorsion n'est pas un décalage entier de pixels — c'est une interpolation continue. Un pixel à (100, 50) peut devenir (101.3, 49.7) après rectification. to_voxel_grid() gère ça avec une interpolation bilinéaire.

④ Voxel Grid — to_voxel_grid()

C'est la représentation centrale de DEVO. On convertit une liste d'events (x, y, t, p) en un tensor 3D (5, H, W) où la 3ème dimension est le temps discrétisé en 5 bins.

Algorithme

Chaque event contribue à 8 voxels voisins (interpolation bilinéaire 3D en x, y, t) avec un poids w = polarity × (1-|dx|) × (1-|dy|) × (1-|dt|). 

# utils/event_utils.py — ligne 180
def to_voxel_grid(xs, ys, ts, ps, H=480, W=640, nb_of_time_bins=5,
                   remapping_maps=None):
    # xs, ys : coordonnées (éventuellement flottantes après undistorsion)
    # ts     : timestamps bruts en µs
    # ps     : polarités 0/1  →  converties en -1/+1

    voxel_grid = torch.zeros(nb_of_time_bins, H, W, dtype=torch.float32)
    voxel_grid_flat = voxel_grid.flatten()

    # Convertir polarité : 0 → -1,  1 → +1
    ps = ps.astype(np.int8)
    ps[ps == 0] = -1

    # Normaliser les timestamps dans [0, nb_bins-1]
    duration = ts[-1] - ts[0]
    t = (ts - ts[0]) * (nb_of_time_bins - 1) / duration
    # t ∈ [0.0, 4.0] pour 5 bins

    # Voisins gauche/droite pour l'interpolation bilinéaire en x, y, t
    left_t,  right_t  = t.floor(),  t.floor() + 1
    left_x,  right_x  = x.floor(),  x.floor() + 1
    left_y,  right_y  = y.floor(),  y.floor() + 1

    # Pour chacune des 8 combinaisons (lx/rx, ly/ry, lt/rt) :
    for lim_x in [left_x, right_x]:
        for lim_y in [left_y, right_y]:
            for lim_t in [left_t, right_t]:

                # Garder seulement les voxels dans les limites
                mask = ((lim_x >= 0) & (lim_x <= W-1) &
                        (lim_y >= 0) & (lim_y <= H-1) &
                        (lim_t >= 0) & (lim_t <= nb_of_time_bins-1))

                # Index linéaire dans le voxel aplati
                lin_idx = (lim_x.long()
                         + lim_y.long() * W
                         + lim_t.long() * W * H)

                # Poids bilinéaire × polarité
                weight = (polarity
                        * (1 - (lim_x - x).abs())
                        * (1 - (lim_y - y).abs())
                        * (1 - (lim_t - t).abs()))

                # Accumuler dans le voxel (opération atomique)
                voxel_grid_flat.index_add_(0, lin_idx[mask], weight[mask].float())

    return voxel_grid  # shape = (5, 260, 346)

⑤ Normalisation — NORM='std'

Avant d'entrer dans le réseau, le voxel est standardisé (mean=0, std=1) sur les pixels non-nuls uniquement. 

# devo/devo.py — ligne 438
# image.shape = (1, 1, 5, 260, 346)

elif cfg.NORM.lower() == 'std':
    flatten_image = image.view(b, n, -1)           # (1, 1, 5*260*346)
    nonzero_ev = (flatten_image != 0.0)
    num_nonzeros = nonzero_ev.sum(dim=-1)

    if torch.all(num_nonzeros > 0):
        # Moyenne et écart-type des pixels NON-NULS seulement
        mean = torch.sum(flatten_image, dim=-1) / num_nonzeros
        stddev = torch.sqrt(
            torch.sum(flatten_image ** 2, dim=-1) / num_nonzeros - mean ** 2)

        # Appliquer la standardisation (pixels nuls restent à 0)
        mask = nonzero_ev.type_as(flatten_image)
        flatten_image = mask * (flatten_image - mean[..., None]) / stddev[..., None]
Pourquoi ne normaliser que les pixels non-nuls ? Le voxel est très sparse (la plupart des pixels = 0 = pas d'event). Inclure les zéros dans le calcul de mean/std fausserait complètement la normalisation. On normalise uniquement là où il y a de l'information.

Il existe 3 modes de normalisation disponibles dans le config :

NORMComportementQuand utiliser
stdStandardise sur les pixels non-nuls : (x-mean)/stdPar défaut pour EVIMO
rescale Positifs → [0,1], Négatifs → [-1,0]. Préserve l'inégalité +/- Quand la distinction +/- est importante
nonePas de normalisationDebug ou encodeur déjà normalisé

⑥ Feature Extraction — BasicEncoder4Evs

L'encodeur CNN prend un voxel (1, 1, 5, 260, 346) et produit deux feature maps : fmap (matching) et imap (context). 

# devo/extractor.py — ligne 269
class BasicEncoder4Evs(nn.Module):
    def __init__(self, bins=5, output_dim=128, dim=32, norm_fn='batch'):
        # bins = nb de canaux d'entrée (= nb_of_time_bins = 5)

        self.conv1 = nn.Conv2d(self.bins, self.dim,   # 5 → 32 canaux
                                kernel_size=7, stride=2, padding=3)
        # Output conv1: (batch, 32, 130, 173)  [H/2=130, W/2=173]

        self.layer1 = self._make_layer(self.dim,       # 32 → 32, stride=1
                                        stride=1)
        self.layer2 = self._make_layer(2 * self.dim,   # 32 → 64, stride=2
                                        stride=2)
        # Output layer2: (batch, 64, 65, 86)   [H/4=65, W/4=86]... mais
        # DEVO utilise seulement la sortie avant stride=2 pour certains maps

        self.conv2 = nn.Conv2d(2 * self.dim, output_dim, # 64 → 128 (ou 384)
                                kernel_size=1)

    def forward(self, x, dual_inp=False):
        # x.shape = (batch, 1, 5, 260, 346)
        b, n, v, h, w = x.shape
        x = x.view(b * n, v, h, w)   # merge batch et time dims

        x = self.relu1(self.conv1(x))   # (B, 32, 130, 173)
        x = self.layer1(x)               # (B, 32, 130, 173)
        x = self.layer2(x)               # (B, 64, 65, 86)
        x = self.conv2(x)                # (B, 128, 65, 86)  pour fmap
        #                                  # (B, 384, 65, 86)  pour imap

        return x.view(b, n, output_dim, h//4, w//4)
Dimensions finales des feature maps (avec W=344 après le hack MVSEC) fmap : (1, 1, 128, 130, 172) — pour la corrélation entre frames
imap : (1, 1, 384, 130, 172) — pour l'update du réseau
Le stride=2 de conv1 divise H et W par 2 (260→130, 346→172 après le crop).

⑦ Patch Selection + Bundle Adjustment

Patch Selection — Scorer

Plutôt que de faire du matching dense sur toute l'image, DEVO extrait 96 patches par frame aux endroits les plus "informatifs" selon un score appris.

with autocast(enabled=cfg.MIXED_PRECISION):

Bundle Adjustment — update()

Pour chaque nouvelle frame, DEVO ré-optimise un graphe de facteurs glissant sur les dernières frames : 

# Pseudocode de la boucle principale
slam = DEVO(cfg, network, evs=True, ht=260, wd=346)

for voxel, intrinsics, t in evimo_evs_iterator(scenedir):
    slam(t, voxel, intrinsics)    # Ajouter une frame
    # En interne :
    # 1. Encoder le voxel → patches
    # 2. Reproj patches → frame courante → résidu optique
    # 3. Réseau prédit la correction de pose Δξ
    # 4. fastba.BA() optimise les dernières OPTIMIZATION_WINDOW=10 frames

poses, tstamps = slam.terminate()
# poses.shape = (N, 7) : [tx, ty, tz, qx, qy, qz, qw]
Fenêtre glissante d'optimisation DEVO ne ré-optimise pas toute la trajectoire à chaque frame — trop lent. Il garde les REMOVAL_WINDOW=22 frames les plus récentes en mémoire et optimise les OPTIMIZATION_WINDOW=10 plus récentes à chaque step. Les frames sorties de la fenêtre voient leurs poses figées.

Notre filtrage NPZ — comment ça s'intègre

L'objectif du filtrage est de supprimer les events générés par les objets mobiles (jouets dans le champ de la caméra) pour ne garder que les events du fond statique, plus utiles pour l'odométrie.

Pipeline du filtrage (scripts/filter_evimo_npz.py)

# Pour chaque event (x, y, t) :
# 1. Trouver le masque le plus proche en temps
nearest_frame = np.argmin(|frame_ts_µs - event_ts_µs|)   # vectorisé

# 2. Lire la valeur du masque au pixel de l'event
mask_val = masks[nearest_frame, event_y, event_x]

# 3. Garder si fond (mask == 0), supprimer si objet (mask > 0)
keep = (mask_val == 0)
evs_filtered = evs[keep]  # (N_filtered, 4)
Les masques NPZ — d'où viennent-ils ? EVIMO fournit des masques pixel-perfect pré-calculés dans les fichiers .npz (à ~/datasets/EV-IMO/eval/<cat>/npz/seq_XX.npz).
mask.shape = (F, 260, 346) avec F ≈ 40–80 frames.
Valeur 0 = fond statique, valeur N×1000 = objet mobile N.
